# Browser Dark Mode

A thin WebExtension that darkens every website, wrapping the vendored
[Dark Reader](https://github.com/darkreader/darkreader) dynamic-theme engine.
One unbundled `extension/` folder loads unchanged in both Chrome and Safari.

## Behaviour (Noir semantics)

Global defaults — Enabled: **Auto** (follows the OS light/dark appearance),
Ignore Built-In Dark Mode: **Off** — plus a per-site override for either
setting (Default / Auto / On / Off). The extension detects sites that already
ship their own dark theme and leaves them alone by default; the popup's
"Ignore Detected Dark Mode" button forces theming anyway for that site. A
same-tab session hint plus a pre-injected fallback style avoid a flash of the
wrong color on repeat visits, at the cost of one flash on a tab's very first
load of a page (guessed by OS scheme) and of a built-in-dark page staying
themed until the detector finishes running.

## Install

### Chrome
1. `chrome://extensions` → enable "Developer mode" → "Load unpacked" → select
   the `extension/` folder.
2. Open any website; it darkens according to the current settings. Click the
   toolbar icon for per-site controls.

Chrome 137+ removed the `--load-extension` CLI flag and Chrome 139+ removed
`--disable-extensions-except`, so only Playwright's bundled (non-branded)
Chromium can load this extension from the command line — "Load unpacked" in
the real Chrome UI is the only way to try it manually.

### Safari — temporary install (no signing, expires after 24h or on quit)
1. Safari ▸ Settings ▸ Advanced ▸ enable "Show features for web developers".
2. Safari ▸ Settings ▸ Developer ▸ enable "Allow unsigned extensions" (this
   toggle resets every time Safari quits).
3. Safari ▸ Settings ▸ Developer ▸ "Add Temporary Extension…" → select the
   `extension/` folder.
4. Safari ▸ Settings ▸ Extensions ▸ enable "Browser Dark Mode" → grant
   "Always Allow on Every Website" when prompted.

### Safari — installed app (Xcode wrapper)
`scripts/safari-convert.sh` runs `xcrun safari-web-extension-converter` to
generate an Xcode project under `safari/` that references `extension/`
directly (no copied resources, so the app always builds from the current
extension code). `scripts/safari-build.sh` then builds it:

- `DEVELOPMENT_TEAM=<team id> bash scripts/safari-build.sh` — automatic
  signing with an Apple Development certificate (free Apple ID added in
  Xcode ▸ Settings ▸ Apple Accounts; the team id is shown there). Xcode
  creates the certificate on first use. The app installs in Safari with no
  per-launch toggle. Verified.
- `bash scripts/safari-build.sh` — ad-hoc (`CODE_SIGN_IDENTITY=-`): the app
  needs "Allow unsigned extensions" toggled in Safari on every launch.
  Verified.
- Developer ID + notarization (for distribution outside the App Store) is
  not covered here.

Run the result once: `open "safari/build/Build/Products/Debug/Browser Dark
Mode.app"`, then enable it in Safari ▸ Settings ▸ Extensions.

## Development
```
npm i && npm run setup && npm test
```
`npm run setup` downloads Playwright's bundled Chromium (one-time,
~150–250MB). `npm test` runs the full Playwright suite against that
Chromium — real, branded Chrome cannot load unpacked extensions from the
command line (see above), so the suite is the only automated check; a human
verifies Chrome/Safari behaviour manually. Use `HEADED=1 npm test` to watch
the browser while debugging a failing test.

## Known limitations (non-goals)
Coexistence with the real Dark Reader extension; re-detection after a site's
own in-page theme switch (until reload or an OS-scheme change); grouping
`www.example.com` with `example.com` (hosts are matched exactly); no
brightness/contrast/sepia/font controls; no per-site fixes configuration or
detector hints; no badge/icon state; Firefox, iOS, and store packaging are
out of scope; `storage.sync` is not used.
